# v1.1.131 marketplace access security review

Security evidence for the `develop` → `master` promotion of v1.1.131 (PR #313). The
release adds in-app project and enterprise management, a Clients tab with private
supporting files, client invitations, project admins by email domain and demo
accounts for testnet.

Other access surfaces in this release:

- **In-app manage bridge** (`ProjectManageAccess`): an Airs session acts with the roles
  and identity stored on its active memberships; global admin status needs a verified
  email listed in `platform_admins`. Internal project and enterprise fields are removed
  for non-global admins.
- **Project admins by email domain** (`20261110_0004`): verified `@alternun.io` users
  receive enterprise memberships (admin on `alternun`, moderator elsewhere). Global
  roles are never granted, global admins are skipped and revoked grants stay revoked.
- **Clients and supporting files** (`20261110_0003`): invitations and proof records are
  server-only tables with RLS; files live in the private `airs-report-proofs` bucket
  (images and PDFs up to 10 MB). The API hashes each file itself and serves 60-second
  signed URLs only to people with `participants:read` on the project. A public URL
  returns 400 and an expired signed URL returns `InvalidJWT`, which was checked on testnet.
- **Demo accounts** (`apps/api/scripts/seed-demo-accounts.ts`): refuses any database
  other than the development project, creates accounts through the Supabase Auth admin
  API and writes generated passwords only to a file outside the repository.

## Regression tests

- `apps/api/test/marketplace-access.security.test.js`: definer functions with a fixed
  `search_path`, execution only by `service_role`, RLS and revokes on the new tables,
  private bucket limits, invite authorization and daily limit, invitation acceptance
  only for the same confirmed account, and the domain-admin guarantees above.
- `apps/admin/test/marketplace-permissions.test.mjs`: console permissions equal the API
  permissions for every role, now including `project_moderator`. Adding the role exposed
  a missing `participants:read` in the console, which this release fixes.
- `apps/api/test/admin-auth.authorization.test.js`: role matrix and "a project moderator
  moderates only within its memberships and never globally".
- `apps/api/test/project-client.test.ts`, `project-manage.test.ts`,
  `admin-access.test.ts`: proof paths confined to the project folder, signed URLs only for
  reports of the same project, view-only moderators, domain sync before roles are read.

## Residual risks

- A signed URL can be opened by whoever holds it while it is valid (60 seconds).
- Demo account passwords are shared with the team; re-running the seed script rotates
  them.
- Email delivery is best effort; failed sends are now logged without the address.
